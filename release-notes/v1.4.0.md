# v1.4.0 — V5：Tunnel Runtime 与 Doctor 修复 + MCP Connector Discovery 兼容

- 发布日期：2026-09-07
- 基准上游：`proma-ai/Proma` `7a3721d7`（本版本为纯二次开发功能版本）

> **关于本 Fork**：本仓库是 [proma-ai/Proma](https://github.com/proma-ai/Proma)（官方上游）的增强 Fork，独立版本号自 v1.0.0 起。功能变更清单见 [docs/fork-maintenance.md](../docs/fork-maintenance.md)。

## P0：Doctor 与 Run 统一 Runtime Credential（V5 §4）

- 新增 `TunnelProcessRunner`：`run` 与 `doctor` 及未来诊断共用同一 `buildTunnelClientEnv()`——之前 doctor 子进程没有注入 `CONTROL_PLANE_API_KEY`，官方 CLI 返回 control plane API key is required；现在两者环境完全一致；
- Runtime API Key 继续只经环境变量注入（safeStorage → Main → 子进程 env），绝不进 argv / 配置 / 日志；进程输出统一脱敏（`redactSecrets`）。

## P0：错误分类区分 Missing / Unauthorized / Forbidden（V5 §5）

- `control plane API key is required` → `RUNTIME_KEY_MISSING_IN_PROCESS`（注入问题，不再误报为权限不足）；
- 401 / unauthorized → `RUNTIME_KEY_UNAUTHORIZED`；403 / forbidden / permission → `TUNNEL_PERMISSION_DENIED`；
- 新增 `RUNTIME_KEY_NOT_CONFIGURED` 语义：Key 未保存时不启动 Doctor 子进程，直接返回明确诊断。

## P0：Doctor 三态诊断（V5 §6/§7）

- 解析官方 `CHECK <name> PASS/FAIL/SKIP` 输出行，映射为用户可读诊断项；
- **Doctor exit != 0 时，未验证项显示 ?（unknown），绝不默认标绿**；只有明确 PASS 的项才显示绿色；
- 技术详情折叠展示 exit code / stdout / stderr（已脱敏），普通用户只见三态图标 + 文案。

## P0：完整 CLI 与 runtime-only 严格区分（V5 §8）

- 程序检测在 `--version` 之外，增加 `doctor --help` 与 `run --help` 校验：`tunnel-client-runtime.exe` 之类的 runtime-only 包会被明确拒绝并提示「请选择完整 tunnel-client.exe 或自动安装」；
- Managed Installer 安装后同样必须通过三重验证才登记可用。

## P0：MCP Connector Discovery 兼容（V5 §9-§11）

- **无状态现代 MCP 请求**：不带 `Mcp-Session-Id` 的 POST 不再被默认当作 initialize——按 JSON-RPC method 分流：`initialize` 走会话模型（legacy 客户端不回归），`tools/list` / `tools/call` 等走 SDK 官方 stateless 模式（每次请求独立 transport，用后即弃）；
- **请求可观测性**：新增最近 50 条 MCP 请求观测（时间 / 方法 / 路径 / 会话有无 / JSON-RPC method / 协议版本 / 状态码；不含任何敏感头与参数），设置页「最近 MCP 请求」实时显示，用户能判断 ChatGPT 请求是否真的到达 PROMA；
- 工具 schema 保持稳定：固定工具集 + workspace 参数 + readOnlyHint 注解（§12），新增/移除仓库不改变工具列表。

## ChatGPT Connector 端到端诊断（V5 §13/§16）

- 新增「连接失败？运行完整诊断」：逐层检查 本地 MCP → /health → 完整 CLI → Runtime Key → Doctor → /readyz → 最近请求 → tools/list 状态，并给出 CASE A（请求未到达，检查 ChatGPT→Tunnel 段）/ CASE B（tools/list 失败，PROMA 协议/schema）/ CASE C（tools/list 200 但 Doctor 有失败项）结论与下一步动作；
- Runtime API Key 文案明确：它不是 ChatGPT 对话用的 Key；推荐权限 Tunnels Read + Use（Manage 一般不需要）；Key 所属主体也须拥有 Tunnel 权限。

## 其他

- Preload bridge 版本升至 **5**；界面检测到旧 bridge 时显示重启指引（不白屏、不调用不存在的 API）；
- Codex OAuth 显式授权原则保持不变：登录只准备授权信息，复制 / 打开浏览器由用户选择；渲染层 Node 边界扫描与生产产物冒烟继续通过（418 源文件 / 780 产物文件）。
