# v1.7.2 — V9 Connector 流量归因、探测隔离与日志入口

本版修复“Tunnel Client 自身探测被当成 ChatGPT Connector 请求”的误诊：空 POST 不再进入 Legacy transport 并产生误导性的 406；内部探测、本地 Client 与 Connector RPC 分开统计。继续使用 V8 官方 MCP SDK 2.0.0。

**本版先作为预发布交付。自动回归通过不代表真实 ChatGPT App 已创建；真实 E2E 仍待完成。**

## 用户可见变化

- 新增 requestKind / requestSource，时间线与“复制协议诊断”显示请求类型、来源分类及转发标记是否存在。
- 空 POST probe 返回稳定 400；无 Session GET 返回 405；OAuth well-known 返回 404。这些探测不会触发 Connector B-TRANSPORT。
- Connector RPC 计数只显示带转发标记的请求，来源未确认 RPC 另列；内部探测、OAuth Probe、Well-known、本地 RPC 独立展示。
- 无 Connector 候选 RPC 时显示 A-UPSTREAM，指向 ChatGPT → Tunnel command → localhost dispatch 排查，避免反复修改 MCP Server。
- Connector Ready 需要实际 Tunnel readiness、现代协议、有效工具列表和带转发标记的 Discovery 链；本地官方 Client 成功不会再冒充 ChatGPT 成功。OK 进一步要求成功工具调用。
- 新增“打开 Tunnel Client Logs”，用户点击后打开当前本地管理地址 /ui#logs，方便核对 command 与 dispatch。
- 两分钟 Protocol Debug 结束后只分析已有记录，不自动运行 Doctor。窗口与主动 Doctor/完整诊断互斥，减少内部探测混入。
- bridge 升至 9；应用 1.7.2，共享契约 0.2.2。

## 回归与安全

- 641 项测试通过，包含本轮 8 项新增测试；类型检查通过。
- Windows 完整 dist:win 打包通过，使用独立 out/v1.7.2 目录；包内 997 个构建文件与最终 dist 校验一致。Electron 43.2.0 / Node 24.18.0 下 CJS MCP 冒烟及 renderer 两级扫描通过。这些验证不替代安装后 GUI 验收。
- 固化文档提供的真实安全请求形状，验证 10 条 probe 只产生 A-UPSTREAM，Connector 406 计数为零。
- 有真实 RPC 结构的 401/406 继续分别归类 B-AUTH/B-TRANSPORT。
- 官方 Client auto/pin 的 modern、tools/list、workspace_list、git_status、read_file 回归保持通过；旧 initialize/session/SSE/DELETE 和 batch 保持可用。
- subject/session 仅记录存在与否，不保存身份值；导出继续排除凭据、工具参数及文件内容。
- 日志入口由主进程读取当前 health URL，仅允许本机 HTTP，拒绝 URL 凭据，丢弃附加 query/fragment；不会自动打开浏览器。
- Release 门禁增加生产构建、renderer 产物扫描及 Electron Node 下的 CJS MCP 冒烟，保留 prepare:electron 和完整测试。

## 如何测试

1. 完全退出旧 Proma，包括托盘，再安装本版。
2. 启动 Local MCP 和既有 Tunnel，等待 Ready；不运行 Doctor/完整诊断。
3. 开启两分钟 Protocol Debug，立即在 ChatGPT 选择同一个 Tunnel，Authentication=none，Create 点击一次。
4. 创建成功后让 ChatGPT 执行“使用 PROMA 列出本地项目”，确认 workspace_list。
5. 若只有 probes、Connector RPC 为零，打开 Tunnel Client Logs 核对是否下发 command、是否 dispatch 到 localhost，再复制安全诊断。

## 已知边界

来源分类依据 HTTP 形状、UA 与 forwarding marker，不等同身份认证；缺少或被代理移除的标记不能提供完整来源证明。自动测试中补充的 UA/marker 明确属于合成测试，不冒充真实 ChatGPT 抓包。

本轮浏览器访问 ChatGPT 超时，尚未取得 App 创建成功或 Tunnel Logs 证明的上游阻断结论。不能仅凭 probe 请求判断 MCP 协议失败，也不能在无日志时宣称上游已故障。

完整设计、来源依据、构建方案与 E2E 流程见 [V9 开发记录](../docs/mcp-v9-traffic-attribution.md)。
