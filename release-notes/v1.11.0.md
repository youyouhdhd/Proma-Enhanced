# v1.11.0 — 独立 ngrok 环境与稳定多项目 Connector

PROMA 现在可以使用自己的 ngrok 配置、加密 Credential 和专用公网地址，与其它项目的 ngrok 环境并行使用。一个固定 ChatGPT Connector 可继续访问动态增删的共享项目。此版本已由用户实测确认可以正常使用。

## 主要更新

- **ngrok 三种运行方式**：新增推荐的「PROMA 独立环境」，同时保留「使用系统 ngrok」和「使用已经运行的 ngrok」。独立配置不保存 Token，不修改系统 ngrok.yml；Credential 使用系统安全存储加密，仅注入 PROMA 子进程。
- **安全复用与冲突处理**：固定地址在启动前执行 Modern MCP、tools/list、workspace_list 完整检查。确认指向当前 PROMA 时直接复用；334 冲突和晚到冲突都会再次验证。其它服务占用地址时提供明确操作建议，不自动 pooling，不停止外部进程。
- **稳定多项目连接**：新增、移除共享项目及调整权限，不会重启 ngrok、改变 Connector URL 或轮换 Secret。移除项目后，后续工具调用立即按新权限拒绝。
- **Provider 程序引导**：自动检测 PATH，展示版本与来源；安装失败提供官方下载入口，手动程序选择收进高级设置。文件选择器按 ngrok、cloudflared、Tailscale、完整 tunnel-client 分别提示，并实际验证程序。
- **设置与诊断**：新增统一字段帮助，区分「本机 MCP 服务」与「远程连接本机端口」；显示配置、认证、Endpoint、公网 MCP 状态及实际 Inspector 地址。
- **Agent 队列**：并发与等待字段对齐并分别提供帮助；最大等待任务支持 0，并发满时立即返回 BUSY。默认仍为 1 个并发、3 个等待任务。

## 升级与使用

1. 原系统认证配置仍按系统模式迁移，保留原域名；原 PROMA 加密认证配置迁移为独立环境。旧域名不会自动认定为 PROMA 独占。
2. 选择独立环境时，保存对应 Credential，并确认 Domain 专供 PROMA 使用。新 Token 不会自动创建 Domain，也不会解除同 Domain 冲突。
3. 启动后等待完整 MCP 检查通过，复制 Server URL 到 ChatGPT。正常增删项目无需重建 App。
4. 仅本机客户端使用「本机 MCP 服务」；公网转发端口位于高级设置，保留现有默认值，通常无需修改。

## 验证

- 用户于 2026-09-11 反馈当前安装版本实测可以正常使用。
- 687 项自动化测试通过，覆盖配置隔离、迁移、Endpoint 复用与冲突、取消竞态、日志脱敏、队列以及 3→4 项目热更新与撤权。
- 全 workspace 类型检查、Electron 构建、Renderer 边界扫描通过。
- Windows x64 包内 Bridge 13、Pi runtime、sharp、node-pty 和 Local/Public MCP 冒烟验证通过；真实 ngrok 3.39.9 独立配置自检通过。

用户实测结论与自动化测试分别记录；自动化 Provider 进程替身不代表对所有 ngrok 账号、套餐或网络环境的保证。ngrok 账号需要提供可供 PROMA 独占的 Endpoint。
