# v1.7.0 — 官方 Modern MCP SDK 迁移与 Connector 协议诊断

本版针对 V7 中“Discovery 返回 HTTP 200，随后进入 initialize/session，出现 POST 406，未执行 tools/list”的问题，正式接入官方 MCP TypeScript SDK 2.0.0。

**验收状态：官方 Client、自动测试和本地 Windows 打包已通过；真实 ChatGPT Connector 创建及安装后界面验收尚未完成。本次先作为预发布提供测试，不宣称 V8 全部验收完成。**

## 协议迁移

- 现代请求默认使用官方 `createMcpHandler`，Discovery schema、`supportedVersions`、每请求 metadata 与服务端身份由 SDK 生成和验证。
- V7 手写 Discovery shim 已退出生产调用链，避免用自定义字段返回一个客户端无法接受的“HTTP 成功”。历史文件暂留，待真实 ChatGPT 验收完成后删除。
- 保留独立的旧 initialize/session/SSE/DELETE 适配器。现代与旧协议使用同一份 LocalToolRegistry、工作区解析和权限检查。
- SDK 2.0.0 的 Server、Node adapter 和测试 Client 精确锁定；没有给 Electron 增加新的 external 或另建模型执行路径。

## 406 与诊断

- 现代终态 JSON 请求兼容 JSON-only 与 JSON+SSE Accept。无法接受 JSON 的请求明确返回 406；支持通配符，并尊重显式 `application/json;q=0`。
- 官方规范仍要求 MCP 客户端声明 JSON+SSE；JSON-only 是本版兼容策略，不能解释为规范已放宽。
- 修复 V7 RPC 响应捕获未接线：JSON 和 SSE 中的错误码都会记录；HTTP 200 内的 RPC 错误不会显示成工具发现成功。
- 新增 unknown / modern / legacy / mixed 时代识别、B-ERA-FALLBACK 和 B-TRANSPORT，保留方法/状态直方图和可展开的拒绝详情。
- 六步诊断区分请求到达、Discovery HTTP/RPC、协议协商、Transport、工具发现和工具调用。Connector Ready 需要实际 Tunnel readiness、现代协商和有效工具列表。
- “开始 2 分钟 Protocol Debug”会实时刷新请求记录，时间到后停止额外请求头采集并自动分析。提供“复制协议诊断”。
- 导出采用显式允许列表，不含 Authorization、Cookie、Runtime Key、本机 Bearer、工具参数、文件内容或原始错误正文。内存记录最多 500 条，单次响应观测最多 256 KiB；超限不会误报 schema 验证成功。
- bridge 升级至 8；界面集中显示应用版本、MCP 协议版本、Tunnel Client 版本。

## 权限与工具回归修复

- 本机 Bearer 缺失或读取失败时拒绝请求，修复旧实现的意外放行。
- 旧 Session 必须匹配创建时的 Profile，不能跨端点复用或删除其他范围的 Session。
- 工具调用也检查全局开关和只读模式，避免仅在 tools/list 中隐藏写工具、却仍能直接调用。
- 文件列表与搜索递归跳过符号链接和 Windows junction，防止读取范围外目录或进入循环。
- 新建尚无提交的 Git 仓库可正常执行 git_status；detached HEAD 仍支持。

## 已验证

- 本地全量测试 633 项通过，类型检查通过。
- 官方 Client auto 与 pin 两种模式均协商为 modern；发现工具并实际执行 workspace_list、git_status、read_file；没有 initialize 回退或 POST 406。
- 官方 schema 验证全部 13 个已暴露工具，包含写文件、编辑文件和 Shell 的定义与 annotations。仓库原本没有 apply_patch MCP 工具，本版没有声称验证不存在的工具。
- HTTP 测试覆盖 JSON-only、JSON+SSE、通配符、拒绝 Accept、Content-Type、协议版本、损坏请求、RPC 错误、认证与 Profile 隔离。
- 旧客户端会话、GET/SSE、DELETE、路径越界及读写权限回归通过。
- Electron 生产构建、renderer 边界扫描和产物静态扫描通过。
- 本地 Windows NSIS 安装包构建通过；打包内 Electron 的 Node 运行模式下，CJS MCP 冒烟通过。
- Release 工作流增加测试/类型检查门禁，构建执行使用 Bun。

## 尚待真实环境验收

- 用户历史两次 POST 406 没有附实际 Accept/Content-Type/MCP 请求头，当前测试使用明确标记的合成 fixtures，不能替代那两条请求的重放。
- 浏览器控制访问 ChatGPT 超时，未完成真实 App 创建、Tunnel Doctor/readyz 联验、首轮工具对话。
- 未执行覆盖安装并操作实际 MCP 设置页的界面验收；renderer 静态扫描和 Electron Node 冒烟不能替代界面验收。
- mixed/fallback 来自同一时间窗口和端点的请求顺序推断；多个客户端同时测试时应结合时间线确认。

## 升级与测试

1. 完全退出旧 PROMA，包括托盘进程，再安装本版。
2. 打开“连接 ChatGPT Web”，确认后台组件为新版本，Local MCP 运行、Tunnel 已连接。
3. 点击“开始 2 分钟 Protocol Debug”，在 ChatGPT 创建 App，选择当前 Tunnel 与既有认证方案。
4. 创建成功后测试：列出本地项目、查看 Git 状态、读取一个已授权文件。
5. 若失败，点击“复制协议诊断”提供安全记录；协议错误无需反复重建 Tunnel、Runtime API Key 或 Role。

开发者命令、迁移依据与回滚方案见 [V8 迁移记录](../docs/mcp-v8-migration.md)。
