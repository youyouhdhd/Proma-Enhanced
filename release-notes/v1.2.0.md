# v1.2.0 — 第二轮优化：OAuth 状态机 + ChatGPT MCP 连接向导 + 多 Workspace Gateway

- 发布日期：2026-09-06
- 基准上游：`proma-ai/Proma` `7a3721d7`（本版本为纯二次开发功能版本）

## 修复：Codex OAuth 登录状态机（P0）

第一轮实现把整个 OAuth 当成一次 request-response，导致「浏览器先打开、授权链接后出现」、表单重挂载丢凭据、重复点击重启流程形成死循环。本版本重构为会话状态机：

- 点击「登录」立即打开授权对话框（显示「正在生成授权链接…」），`codex-oauth:start` 立即返回 `sessionId`，登录在主进程后台继续；
- `auth_url` / `device_code` / `manual_input_ready` / `progress` / `success` / `error` 全部作为会话事件推送（`channel:codex-oauth-event`），渲染层只接受当前 `sessionId` 的事件，旧会话迟到事件丢弃；
- 自动打开浏览器每个会话最多一次（`browserOpened` 守卫）；`shell.openExternal` 从 OAuth 服务移除，改由会话控制器统一决策；
- 手动 callback 只 resolve 当前会话（`submit-callback` 携带 `sessionId`），解析、state 校验与 token 交换仍全部由 Pi 在原流程内完成，绝不重启登录；
- 双击登录复用同一会话（`reused=true`），绝不创建并发 OAuth；
- success 后 active session 清空，程序自动关闭对话框时不再触发 cancel（`autoClose` 守卫区分用户取消与成功收尾）。

验收：从点击「登录」到成功只存在一个 OAuth session；`auth_url` / `state` / `PKCE verifier` / `localhost callback` / `manual callback` 全程同一个。

## 新增：多 Workspace MCP Gateway（P1）

把「一个 MCP 绑定一个仓库」升级为「一个 Gateway 管理多个 Workspace」：

- Workspace 注册表：每个项目独立授予 读取 / 写入 / 执行命令 权限（`ws_xxxxxxxx` 稳定 id 由 Agent 工作区 id 确定性派生）；不存在全局 activeWorkspace，工具调用显式携带 `workspace_id`（仅授权一个项目时可省略）；
- 新工具：`workspace_list`（列出项目 + 分支 + 权限）、`read_many`（跨仓库批量读取，20 文件 / 400KB 预算）、`git_status_batch`（多仓库批量状态）；`search_text` 支持 `workspace_ids` 跨仓库搜索，结果带 `workspace_id` 标记；
- 固定工具集 + 仓库作为运行时参数：新增 / 移除项目无需修改 MCP tool schema，ChatGPT 下次 `workspace_list` 即可发现；
- 工具注解：read 工具 `readOnlyHint=true`，write/execute `destructiveHint=true`，帮助 ChatGPT 正确处理确认与权限；
- Connection Profiles（高级）：同一 HTTP Server 上按 endpoint 隔离项目子集（如 `/mcp/work`），支持多 ChatGPT App / Tunnel 场景。

## 新增：ChatGPT 连接向导 + Secure Tunnel 集成（P1）

- 设置页重设计为「连接 ChatGPT Web」五步向导：Overview（这是什么 / 流程图）→ Projects（项目授权 + 独立权限）→ Local MCP（状态 / 端口 / 认证 / 工具组折叠）→ OpenAI Secure Tunnel → ChatGPT Setup（逐步教程）→ Advanced（Profiles）；
- OpenAI Secure MCP Tunnel 集成：保存 Tunnel ID + Runtime API Key（Electron safeStorage 加密落盘，不进配置文件 / 命令行 / 日志，启动时经 `CONTROL_PLANE_API_KEY` 环境变量注入），一键启停 `tunnel-client` 并运行 `doctor` 诊断；
- 明确说明 localhost 地址不能直接填入 ChatGPT、Tunnel 只负责转发、各步骤的负责方（PROMA / OpenAI / ChatGPT）。
