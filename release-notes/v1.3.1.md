# v1.3.1 — 修复：MCP 设置页生产构建白屏 + 渲染层稳定性强化

- 发布日期：2026-09-07
- 基准上游：`proma-ai/Proma` `7a3721d7`（本版本为纯二次开发修复版本）

> **关于本 Fork**：本仓库是 [proma-ai/Proma](https://github.com/proma-ai/Proma)（官方上游）的增强 Fork，在官方版本基础上进行二次开发；独立版本号自 v1.0.0 起，不跟随上游版本号。

## 问题

第三轮 MCP 设置页改造在渲染层 JSX 中直接引用了 `process.platform`。Proma 主窗口使用 `contextIsolation: true + nodeIntegration: false`，且 Vite 不提供 process polyfill，生产构建中该调用未被替换，进入 MCP 设置页时抛出 ReferenceError，右侧内容区域整体白屏，只剩应用背景。

## 修复（P0）

- 删除渲染层对 `process.platform` 的直接依赖：程序名称文案直接写「tunnel-client（Windows 下通常为 tunnel-client.exe）」；不做 `typeof process` 规避，不开启 nodeIntegration，不加 polyfill。

## 稳定性强化（按开发文档逐项落地）

- **Preload API 防崩**：MCP 页面所有 preload 依赖按能力检测使用；`onMcpTunnelStateChanged` 缺失时实时状态降级为手动刷新并输出警告，页面继续显示；
- **Bridge 版本协商**：preload 暴露 `bridgeVersion: 3`；界面检测到版本过旧时显示「后台组件需要重新加载」的明确操作指引（完全退出 → 退出托盘 → 重启），不再白屏；
- **Error Boundary**：新增 `McpServerSettingsErrorBoundary` 并在 BotHub 中包裹 MCP 页面——任何渲染异常都会显示「MCP 设置页面加载失败 + 配置未被删除 + 重新加载」，技术详情折叠展示；
- **配置防御 normalize**：渲染层对 `mcpServer` 做最低级 normalize（workspaces / profiles / tools / auth 缺失不崩；Main 层 `normalizePromaMcpServerConfig` 安全边界保持不变）；
- **Tunnel 状态防御**：新结构补齐、旧结构（status/clientInstalled）迁移、无法识别回退安全状态；事件负载同样过 normalize；
- **数据加载隔离**：Tunnel 状态加载失败只降级 Tunnel 区域；工作区列表加载失败显示空列表——两者都不再影响其余步骤显示；
- **可观测性**：挂载时输出 preload 能力清单（只记录存在性，不含敏感配置）。

## 回归防护（防再发）

- `check:renderer-boundaries`：静态扫描渲染层源码，阻止新增 `process.* / require() / __dirname / child_process / node: 导入 / Buffer.*`（当前 418 个文件零命中）；
- `smoke:renderer-dist`：对生产构建产物扫描未替换的 `process.platform / process.env`（当前 780 个产物文件干净；shiki 主题惰性分块为已知 vendor 例外并注释原因）。
