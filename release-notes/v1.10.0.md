# v1.10.0 — V12 完整 MCP 能力、稳定 ngrok 与多模型分析

本版重点让一个长期使用的 ChatGPT Connector 访问多个动态共享项目，同时开放由用户控制的 Direct 写入与 Shell。由于真实单 Plugin 多项目 ChatGPT 验收尚未完成，本版为预发行测试版。

## 主要变化

- **多项目共用连接**：新增 workspace_open，按名称或 ID 返回项目标识。新增、移除和修改项目权限不会重启 Provider、轮换 Secret 或改变工具定义指纹；多项目操作必须显式指定 workspace_id。
- **Direct 写入与 Shell**：在全局能力、工具组和项目权限同时允许时，远程 Client 可调用既有 write_file、edit_file、shell_execute。默认仍关闭写入与 Shell，旧版本升级不会扩大权限；缓存调用也会重新检查权限。
- **独立 ngrok Provider**：默认复用系统 ngrok 配置，支持可选 PROMA 加密 Token、自定义 YAML、固定账号域名和自动临时地址。默认不再生成关闭 Inspector 的临时配置。
- **多渠道多模型分析**：支持批量选择目标、Fallback、轮询与 Manual，配置并发和等待数量。取消会阻止后续 Fallback，任务固定原项目；直接工具不消耗模型额度，分析任务使用所选渠道额度。
- **日志与诊断**：保留脱敏 stdout/stderr、进程退出前日志及错误详情；新增完整连接自检、日志筛选/复制/清空、参数帮助和调用耗时记录，不默认记录完整工具参数或文件内容。
- **批量管理**：支持批量选项目、文件夹及读取/写入/Shell 权限。紧急撤销会停止远程访问、中止活动任务并轮换 Connector Secret。

## 升级后如何使用

1. 先检查共享项目及每个项目的 Read/Write/Shell 权限。
2. 在能力设置选择安全读取，或明确开启需要的 Direct 能力；Shell 的工作目录守卫不是操作系统沙箱。
3. ngrok 默认选系统配置。已完成 `ngrok config add-authtoken` 的用户无需再次粘贴 Token；填写账号 Assigned Domain，检测后启动。
4. 公网检查通过后，将复制的 Server URL 配到 ChatGPT。新增项目只需再次 workspace_list，无需重建 Plugin；开启新工具后按提示 Refresh。
5. 需要 PROMA 分析时启用多模型目标，至少一个目标已授权即可。模型目标改变不会改变公网地址。

## 验证与限制

- 脚本测试使用隔离目录和模拟模型运行器，不消耗付费模型额度；覆盖热更新、权限拒绝、真实本地 MCP 写入/Shell、迁移、日志脱敏和模型路由。
- 本机真实 ngrok config check 通过，只代表配置有效；固定域名公网重启与 ChatGPT 单 Plugin 多项目链路仍待人工验收。
- 真实启动中修复了通用代理环境继承导致的 ERR_NGROK_9009；修复后当前账号域名被已有连接占用（ERR_NGROK_334），保留用户原连接，未强行接管。两类错误现在都有独立诊断。
- 图形浏览器控制连接超时，安装后设置页交互仍需人工检查。
- Approval 暂未开放；按 V12 第 7 节先交付 Disabled + Direct，approval 配置会拒绝执行。Parallel 与 ChatGPT 附件导入属于后续非阻塞项。
- 已完成的文件写入不能通过“紧急撤销”回滚。持有 Connector URL 的 Client 拥有已明确开放的权限，请妥善保管。

实现边界、迁移与复现命令见 [V12 开发记录](../docs/mcp-v12-implementation.md)。最终构建及附件状态以本版本 Actions 结果为准。
