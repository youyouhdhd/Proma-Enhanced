# v1.5.0 — V6：Connector / Tunnel / Local MCP Auth / Doctor / 可观测性收敛修复

- 发布日期：2026-09-07
- 基准上游：`proma-ai/Proma` `7a3721d7`（本版本为纯二次开发功能版本）

> **关于本 Fork**：本仓库是 [proma-ai/Proma](https://github.com/proma-ai/Proma)（官方上游）的增强 Fork，独立版本号自 v1.0.0 起。功能变更清单见 [docs/fork-maintenance.md](../docs/fork-maintenance.md)。

## P0-1：Runtime API Key 状态以凭据存储为事实来源（V6 §5-§8）

- 修复「Key 已保存但 UI 仍显示尚未保存」：Tunnel 状态改为派生快照（`buildStateSnapshot()`），`runtimeKeyConfigured` / `runtimeKeyStatus` 每次从 safeStorage 实时推导；`saveRuntimeKey()` 写入后回读验证（roundtrip 失败即抛错）并立即 emit 推送 UI；
- 新增凭据健康三态 `missing / available / unreadable`：文件存在但解密失败显示「✕ 已保存的 Key 无法读取」而非绿色；
- 新增「清除已保存的 Runtime API Key」按钮（二次确认）。

## P0-2：Doctor 不再占用 127.0.0.1:8080（V6 §9）

- `doctor` 与 `run` 一样使用 `--health.listen-addr 127.0.0.1:0` + `--health.url-file`（系统分配空闲端口），8080 被占用不再导致 Doctor 假失败；Doctor 临时文件成功 / 失败 / 超时 / spawn error 都在 finally 中清理。

## P0-3：Doctor Parser 对齐官方真实 Check（V6 §10-§11）

- 按官方 v0.0.14 实际输出映射：`config_source / profile_load / tunnel_id / control_plane_api_key / mcp_target / mcp_server_reachable / oauth_metadata / health_listener / ui / codex_plugin` 等；
- 删除 V5 时期虚构的 `tunnel / control_plane_connection / mcp_server / secure_tunnel_ready` 期望项——不再出现大量「未完成验证」；
- `Secure Tunnel /readyz` 独立为 Runtime Readiness，不再伪装成 Doctor 检查；`codex_plugin SKIP`、`ui SKIP` 不是 ChatGPT Connector 阻断项；新增 `blockingFailures` 明确列出真正阻断的关键失败。

## P0-4：Local MCP Bearer 认证与 Tunnel Client 集成（V6 §12-§16）

- 新增认证模式 `managed-bearer`（推荐）：PROMA 自动生成随机 Secret 并存 safeStorage（settings.json 不落明文）；旧 bearer 明文配置启动时自动迁移；
- Local MCP 开启本机认证时，PROMA 经环境变量 `PROMA_MCP_AUTH_HEADER`（完整 `Bearer <secret>`）注入，tunnel-client 通过 `--mcp.extra-headers` / `--mcp.discovery-extra-headers` 的 `env:` 引用转发——Secret 绝不进 argv；
- Doctor 与 Run 使用同一 `TunnelRuntimeConfig` / env：Doctor 对 bearer MCP 的探测不再 HTTP 401；
- ChatGPT 侧 Connector 仍选「无身份验证」：本机 Bearer 是 tunnel-client → PROMA 的内部认证，与 ChatGPT 用户认证无关。

## P0-5：HTTP 401 语义升级 + Auth Reject 进入观测（V6 §17-§20）

- Doctor `mcp_server_reachable PASS HTTP 401` 不再当作可用：诊断生成 `PROMA MCP 内部认证` 失败项（401 / 403 分别提示）；
- 请求观测覆盖认证拒绝：401/403 也记录 trace（`authResult: rejected`），Connector 诊断不再把「本机认证拒绝」误判成「未收到任何请求」；
- 新增 **CASE B-AUTH**：请求已到达 PROMA 但被本机认证拒绝（与 CASE A / CASE B-PROTOCOL / CASE C 明确区分）；
- 「开始一次 Connector 测试」窗口：只统计该时间之后的请求，避免历史干扰。

## 其他

- 最近请求 UI 按状态着色（2xx 绿 / 401·403 红 / 其他 4xx 橙）并显示「认证拒绝」；
- Preload bridgeVersion 升至 **6**；旧 bridge 显示重启指引，不白屏；
- 保持：stateless MCP Discovery、多 Workspace Gateway、safeStorage、shell:false、Codex OAuth 显式授权、渲染层边界扫描与产物冒烟（418 源文件 / 780 产物文件零命中）。
